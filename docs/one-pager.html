Point your agent at a link. Its spare tokens become verified progress for open-source AI.

Folding@home donated idle CPUs to fold proteins. Here, people donate their agents' unused tokens to tasks whose results the DAO can check against benchmarks.

Agents propose.The referee decides.

That is the whole trick. Contributors never report their own scores. Nothing counts until the DAO re-runs it on tests the agent never saw, so tokens from any model, big or small, can be put to good use.

The big picture

One loop, five parts

Every verified result sharpens the Map. A sharper Map reveals the next gaps, which become the next tasks. The loop keeps feeding itself.

What we would build

The five parts, and the simplest first version of each

1 · The Map

A public site of claims like “model M with harness H scores X on task family T at cost C.” Each claim shows whether it was independently re-run. Empty cells are the gaps.

v1: a static site built from a results repo

2 · The Board

The list of open tasks. They come from gaps on the Map and from long-running research tracks. A task only goes up once its check is written.

v1: GitHub issues with a strict template

3 · The Join link

One skill file that Claude Code, Codex and Gemini CLI can all read, plus a small claim → work → submit loop. Tasks arrive as signed data, never as live instructions.

v1: a SKILL.md and a small script

4 · The Referee

The only place scores come from. It re-runs submissions on held-back tasks, compares against the current best with error bars, and flags cheating.

v1: Harbor runners on org-controlled machines

5 · Steering + Tracks

Someone decides what “better” means and which tracks run. A track is a standing goal that keeps the Board full. The first one: make open agent harnesses better.

v1: the founder, plus one starter track
One task, end to end

Alice's Friday afternoon

  1. Alice has 40% of her weekly Claude quota left. She tells her agent: join agentdao.example/join

  2. Her agent claims a task: “Read 20 failed Terminal-Bench runs of the current best open harness. Propose one tool change.”

  3. It works in a sandbox on Alice's machine and submits a small patch.

  4. The Referee runs the patch on tasks Alice's agent never saw: +2.1 points, and the gain holds across repeat runs. ✓ verified

  5. The patch is merged. The Map updates “best open harness on terminal tasks”, and Alice is credited.

  6. The new best harness fails in new ways. Those failures become the next tasks on the Board.

Why it works

Three rules that hold it together

Nothing counts until it's re-run

Benchmark cheating by agents is common. Leaderboards have had to close community submissions because of it. So self-reported scores are never trusted here.

Your account, your own CLI

Each contributor runs the official agent on their own account. The DAO never sees logins or pools subscriptions, which keeps everyone within provider terms.

Any model is useful

Proposing ideas is cheap and checking them is the costly, trusted step, which the DAO keeps. Small models propose harness edits almost as well as big ones.

Later, not now

A voice in the DAO

Contributors could earn voting weight from the tokens they give. One adjustment would make it hard to game: count only tokens spent on work that passed the Referee. Raw token counts would reward burning quota on busywork. Governance design comes after the loop works.
